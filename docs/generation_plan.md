# 生成計画（GNB-ZipImageCompressor）

## 概要
このドキュメントは `docs/README.md`（企画書）に基づき、GNB-ZipImageCompressor の開発・生成（ビルド・テスト・パッケージング）計画を示します。目的は、ZIP 内の PNG/JPG を WebP に変換し、Zstd を用いた ZIP 再圧縮でファイルサイズを削減する Windows デスクトップアプリを安定して提供することです。

## 目標（成功基準）
- 機能要件を満たす動作する Windows 実行ファイル（gnb-zicomp.exe）を生成できること。
- 代表的な ZIP ファイル（画像大量含む）で、変換後 ZIP のサイズがオリジナルより小さくなること（目安: 平均 20% 以上の削減を期待）。
- 複数インスタンス同時実行でテンポラリ競合がないこと。
- CI 上でユニットテストと主要な E2E（サンプルファイル）を回せること。

## 前提・仮定
- 対象 OS: Windows 11 のみ。
- 開発言語: Svelte（フロントエンド）、Rust（Tauri バックエンド）。
- ZIP 処理は `zip` crate（Zstd サポート）を利用する。
- WebP 変換は `image` crate などで実現する（必要に応じ native binding を検討）。

## 検証・テスト計画
- ユニットテスト:
  - ファイルパス処理、テンポラリ動作、画像判定、変換成功/失敗ハンドリング。
- E2E:
  - 正常系: 画像多数を含む ZIP を処理して期待通りの出力が得られるか。

- パフォーマンス測定:
  - 代表的なサンプルで処理時間と最終 ZIP サイズを比較（ベンチマーク記録）。

## リスクと軽減策
- 画像変換での互換性問題 (例: image crate の WebP サポート不足)
  - 軽減: libwebp などネイティブバインディングを検討、または外部変換ツールの呼び出しを検討。
- ZIP クレートの Zstd サポート差異
  - 軽減: `zip` と `zstd` の組み合わせでテストし、必要なら別実装（直接 zstd 圧縮ファイルを作成）を検討。
- Windows ショートカットからの作業フォルダ取得の複雑さ
  - 軽減: 実装を抽象化して失敗時はデスクトップへフォールバック。
