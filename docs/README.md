## ソフトウェア企画書：GNB-ZipImageCompressor

-----

### 必須項目

#### プログラムの名称

**GNB-ZipImageCompressor** (ジーエヌビー・ジップイメージコンプレッサー)

#### 目的

ユーザーが指定した**ZIP**圧縮ファイル内の**PNG/JPG**画像を、ファイル名を維持しつつ**WebP**形式に変換し、さらに**標準的なZIP圧縮（Deflate）**で再圧縮することで、**ファイルサイズの削減と高速な圧縮/解凍**を実現する。特に、Webコンテンツの軽量化と転送効率の向上を目的とする。

#### 機能

  - **ドラッグ＆ドロップ機能:** Windowsの**ショートカット**またはGUI領域に、**ZIPファイル**をドラッグ＆ドロップして処理を開始。**複数ファイル同時ドロップの場合、最初の1ファイルのみ処理し、残りは無視する。**
  - **対応圧縮形式の解凍:** **ZIPファイル**（読み込み専用）を、**OS標準の一時フォルダ内**に、**インスタンスごとに一意な名前のサブフォルダ**を作成して解凍する。
      - **エラー処理:** オリジナルの圧縮ファイルに不具合があるなど、解凍プロセスでエラーが発生した場合は、**全処理を直ちに中断**する。
  - **画像変換処理:**
      - 解凍されたファイル内から**PNG**、**JPG**、**JPEG**ファイルを検索。
      - **マルチスレッド処理:** **CPUコア数**を最大スレッド数とする**スレッドプール**を使用し、**画像ファイル単位で非同期処理**を行う。
      - 検出された画像を**WebP**形式に変換。
          - **変換品質:** **可逆圧縮(Lossy) 75**を初期品質として採用。設定値の変更は今後の課題（設定ファイルJSONでの直接編集）。
      - 変換後のファイル名は、**元のファイル名（拡張子を除く）を維持し、拡張子を`.webp`に変更**する。
      - **元の画像ファイルは削除**。
      - **非対応ファイル:** **画像形式の非対応ファイルは処理せず、そのまま再圧縮の対象とする。**
  - **再圧縮:** WebPに変換されたファイル群を**ZIP形式**で再圧縮。
      - **ファイル名エンコーディング:** ZIP圧縮時のファイル名は**UTF-8**でエンコードする。
  - **実行ファイル名:** **`gnb-zicomp`**
  - **出力先制御:**
      - **出力フォルダー決定ロジック:**
        1.  ショートカットへのドロップまたはショートカットからのGUI起動の場合、カレントワーキングディレクトリの値があればそのフォルダーを出力先とする。
        2.  それ以外の場合（「作業フォルダー」がない、または実行ファイルを直接実行した場合）、**デスクトップ**を出力先とする。
      - **出力ファイル名決定ロジック:**
        1.  新しい圧縮ファイルの**ファイル名**を、元のファイル名（例: `original.zip`）の拡張子を`.zip`としたもの（例: `original.zip`）で決定する。
        2.  **決定された出力フォルダー**に、そのファイル名（例: `original.zip`）のファイルが**存在しない場合**、このファイル名をそのまま新しいファイル名とする。
        3.  **存在する場合**、元のファイル名に**サフィックス**（例: `-zicomp`）を追加し、ファイル名を（例: `original-zicomp.zip`）とする。
  - **テンポラリフォルダのクリーンアップ:** 処理完了後、インスタンスが作成した**テンポラリフォルダを自動的に削除**。
  - **GUI表示:** 処理の進捗状況と**決定された出力先パス**を表示。
    ```
    ----
    処理ファイル：<処理中は元のファイル名を表示、終わったら空白>
    出力フォルダー：<出力フォルダー>
    ☑ 解凍<処理・中・完了>
    □ 変換<処理・中・完了>
    □ 圧縮<処理・中・完了>
    ----
    ```

#### 開発言語

  - **フロントエンド/GUI:** **Svelte** (HTML, CSS, JavaScript)
  - **バックエンド/コアロジック:** **Rust** (Tauriのバックエンド)

#### 実行環境

  - **OS:** **Windows 11** (専用)
  - **ランタイム:** **Tauri 2.0**ランタイム
  - **デプロイ形式:** Windows 11向けの**デスクトップアプリケーション**（実行ファイル形式）
  - **オフライン専用**

#### 主要ライブラリ

| ライブラリ | 用途 |
| :--- | :--- |
| **Tauri 2.0** | デスクトップアプリケーションのフレームワーク。RustとWeb技術（Svelte）を統合。 |
| **Svelte** | 高速なユーザーインターフェースを構築するためのフロントエンドフレームワーク。 |
| **`zip` crate (Rust)** | ZIPファイルの解凍と作成。**標準的なZIP圧縮アルゴリズムの適用**、**UTF-8ファイル名エンコーディング**。 |
| **`image` crate (Rust)** | 画像ファイル（PNG, JPG, JPEG）の読み込み、WebP形式への変換（Lossy 75設定）。 |
| **`rayon` crate (Rust)** | 画像変換処理の並列化。CPUコア数を自動的に利用し、効率的な並列処理を実現。 |
| **`tempfile` crate (Rust)** | **OS標準の一時フォルダに、安全で一意な一時ファイル/フォルダを作成**するために利用（バージョン3系）。 |

### 追加提案項目

#### 対象ユーザー

**不特定のユーザー**。ウェブサイト管理者、ブロガーなど、**画像を多く含むファイルを頻繁に共有またはアップロードする個人ユーザー**。

#### 非機能要件

| 要件カテゴリ | 概要 |
| :--- | :--- |
| **インスタンス** | **複数インスタンスの同時実行に対応**。各インスタンスは独立して動作し、テンポラリフォルダや設定ファイルで競合を起こさない。 |
| **パフォーマンス** | **標準ZIP圧縮**の採用と、**Rayon**による並列処理により高速化を図る。|
| **セキュリティ** | 外部ネットワークとの通信を行わない（完全にローカルで動作）。テンポラリファイルは処理後すぐに削除。 |
| **信頼性** | ファイルI/O、解凍/圧縮、画像変換時のエラー発生時は、分かりやすいメッセージでユーザーに通知し、安全に処理を中断。|
| **可用性** | **オリジナル圧縮ファイルは読み込み専用**として処理し、誤って元のファイルを破壊することを防ぐ。 |
| **ユーザビリティ** | シンプルなGUI。ドラッグ＆ドロップ操作のみで主要な機能が利用可能。 |
| **制約** | **Windows 11専用**、**オフライン専用**。Mac/Linux対応予定無し。 |
| **拡張予定** | CLI非対応、圧縮ファイル・画像ファイルの他形式の対応は要検討。|
| **ライセンス** | **オープンソースライセンス**（例: MITまたはApache 2.0）に準拠。|

#### アーキテクチャ概要

**シンプルな二層アーキテクチャ**

  - **プレゼンテーション層 (Svelte):**
      - ユーザーインターフェース（GUI）の表示とウィンドウの状態保存/読み込み。
      - ドラッグ＆ドロップイベントの処理。
      - バックエンド（Rust）へのコマンド発行と、進捗情報、エラーメッセージの表示。
  - **コアロジック層 (Rust/Tauri Backend):**
      - **ファイルI/O:** `tempfile`クレートを用いたテンポラリフォルダの作成、解凍、変換、圧縮、削除。
      - **OS連携:** カレントワーキングディレクトリ取得、デスクトップパス取得。
      - **並列処理:** `rayon`を用いた画像単位の並列処理実行。
      - **設定管理:** ウィンドウ状態の読み書き。

#### GUIウィンドウサイズ・位置の保存方法の提案

レジストリを使用せず、単純で削除しやすい方法として、**アプリケーションデータフォルダ内のJSONファイル**を用いた保存を推奨します。

  - **保存パス:** `%APPDATA%\gennobou\gnb-zicomp\window_state.json`
  - **方法:** Rustバックエンドが、ウィンドウの位置（`x`, `y`）とサイズ（`width`, `height`）の情報をJSON形式で`window_state.json`に保存・読み込みする。

#### テスト計画

  - **ユニットテスト:** Rustのコアロジック層（ファイルパス処理、画像形式判定、WebP変換処理、Zstd圧縮、テンポラリフォルダ管理など）に対して`cargo test`を用いて実施。
  - **E2Eテスト:** 実際のファイルを使い、以下のシナリオを確認。
      - ショートカットからのドロップ、実行ファイルからの起動で、出力先が正しく決定されるか。
      - 複数インスタンスを同時起動し、それぞれが独立して処理を完了し、テンポラリフォルダを正しく削除するか。
      - **破損ファイル**をドロップした場合に、**全処理が中断**され、エラーメッセージが表示されるか。

#### デプロイメント方法

1.  **ビルド:** Tauriのビルドコマンドを実行し、\*\*Windows向けの単一実行可能ファイル（EXE）\*\*を生成。
2.  **配布:** GitHubの**Releases**ページに実行ファイルをアップロード。ユーザーはこれをダウンロードし、任意の場所に配置して利用。
3.  **コード署名:** 今後の課題とする。
4.  **ライセンス:** **オープンソースライセンス**（例: MITまたはApache 2.0）を適用し、GitHubで公開する。
